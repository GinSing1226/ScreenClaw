

# 产品需求与技术方案文档：桌面安卓模拟器无感 RPA 代理网关 (AutoEmu-Bridge)

## 一、 项目背景与核心愿景
当前大量的桌面多模态 UI-Agent（如 OpenClaw、AppAgent 等）在控制 PC 安卓模拟器时，存在两个致命痛点：要么高度依赖繁琐的 ADB 配置（小白用户劝退），要么抢夺用户的物理鼠标键盘（无法后台运行）。

**AutoEmu-Bridge** 的定位是一个**极其轻量的、对其他 Agent 开放的“纯本地基础设施/中间件”**。
本程序**不包含任何 AI 模型和复杂推理逻辑**。它的唯一职责是：
1. 在**后台无感**地截取安卓模拟器画面，叠加视觉坐标系（网格/标记），存放到本地供外部 Agent 读取。
2. 监听外部 Agent 输出的指令文件（JSON），将绝对坐标或网格标号解析为底层的系统句柄指令（或本地微型 ADB 指令），向模拟器**注入后台点击/滑动操作**。
3. 全程不抢夺用户真实的物理键鼠，允许用户在看电影、写文档的同时，Agent 在后台模拟器中完成自动化任务。

---

## 二、 系统架构与工作流（Data Flow）

本系统与外部 Agent 采用**“基于本地文件系统的生产者-消费者模式”（File-based IPC）**或 **微型本地 HTTP 服务** 进行解耦交互。工作闭环如下：

1. **状态就绪：** 用户通过我们的 GUI 面板启动程序，选择目标模拟器（如雷电/MuMu）。程序建立后台句柄锁定。
2. **生产环境感知（Screen Capture & Mark）：** 
   - 程序通过 Windows底层 API 在内存中抓取模拟器无遮挡画面。
   - 使用图像处理库在画面上**叠加半透明坐标网格（或元素锚点标记）**。
   - 将叠加好的图片保存到本项目根目录data文件夹下。

3. **消费动作指令（Action Execution）：**
   能让用户在终端发送指令，然后你操控被监控的进程。优先实现通过窗口句柄去操控：
   - 点击：点击某处
   - 长按：在某个位置长按xx秒
   - 滑动：长按鼠标并滑动一定距离
   - 截图：收到命令就截图，保存到本地

## 三、 核心技术模块与功能需求

请开发团队重点关注以下四大核心模块的纯 Python 实现：

### 模块 1：窗体劫持与进程锁定 (Window Manager Module)
*   **需求描述：** 根据用户选择，查找对应安卓模拟器的进程及窗体句柄（HWND）。
*   **技术要求：**
    *   禁止只获取顶层外壳句柄！大多数模拟器（雷电、MuMu）分为外壳控制面板和内部渲染器。必须通过 `win32gui.EnumChildWindows` 遍历找到真正显示游戏/APP 画面的 **内部渲染子句柄 (Render/OpenGL 子窗体)**。
    *   需获取并持续监控该子句柄的实时分辨率（Width, Height），作为后续坐标转换的基准比例尺。

### 模块 2：后台图像提取与网格化打标 (Vision Prep Module)
*   **需求描述：** 无视窗体遮挡提取画面，并加上人类和 AI 都能看懂的网格/坐标系后落盘。
*   **技术要求：**
    *   **提取（抓图）：** **严禁使用 `PyAutoGUI` 或 `ImageGrab` 抓取桌面全屏。** 必须通过 `win32gui.PrintWindow(hwnd, hdc, 3)` (或更底层的 `BitBlt` / Windows.Graphics.Capture API) 从后台抓取显存级干净截图。
    *   **打标 (Set-of-Mark)：** 在抓出的图像对象上，使用 `Pillow` 等库画上一层类似国际象棋盘的网格。将宽度和高度用百分比打标，例如每搁10%打标一次，在每个交叉点里标上数字（0.9,0.9）意味着是宽度90%、高度90%的坐标。
    *   **落盘：** 以尽可能低延迟的 I/O 保存至本地。

    *   **坐标转换：** 若在终端收到指令，你需要将坐标转化为“模拟器渲染子窗体”内部环境的 `(x_relative, y_relative)` 坐标值。

### 模块 4：纯后台物理隔离引擎 (Silent Execution Engine)
*   **需求描述：** 将推算好的坐标点击进去，**绝对不抢夺用户的系统级真实鼠标与光标流**。
*   **技术选型建议（策略模式提供双备选）：**
    *   **首选策略 (Win32 后台消息流)：** 构建 `lParam = win32api.MAKELONG(x, y)`，向该子句柄连续发送 `win32con.WM_LBUTTONDOWN` 和 `WM_LBUTTONUP`，实现毫秒级“幽灵点击”。
 

### 模块 5：客户端操作控制面板 (GUI Client)
*   **需求描述：** 给 C端 小白用户的一个非常清爽的控制启停界面。
*   **技术要求：** 采用 `CustomTkinter` 或 `PySide6`。
    *   一个下拉菜单：展示当前电脑开启的“疑似模拟器进程（HWND 列表）”，供用户选择挂载。
    *   一个大型的【开始托管 / 停止托管】按钮。
    *   一个简单的运行日志状态栏（显示：“已生成图片...”，“收到外部 Agent JSON，执行点击 C-5 成功”）。
    *   （可选）支持最小化至 Windows 右下角系统托盘区运行。

## 四、 特别安全与风险提示 (Risk Management for Dev)
1. **防止无限循环/误点：** 在模块 4 执行操作前后，程序应有 1-2 秒的随机/固定延迟 Sleep 操作，严防因外部 Agent 频繁发消息导致电脑被卡死（DDos级别的高频模拟）。并在系统右下角保留强制停止全局热键（如 `Ctrl + Shift + F12`）切断循环队列。
2. **窗体丢失检查：** 在每执行一轮之前检查 `win32gui.IsWindowVisible(hwnd)`，如果用户关闭了模拟器，应捕获异常并回到待机状态。
