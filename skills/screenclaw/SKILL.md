# ScreenClaw 技能

通过HTTP API控制ScreenClaw实现桌面软件自动化操作。

## 快速开始

### 标准工作流程
```
0. [初始化] 生成唯一 session_id，整个会话保持不变
1. 读取 /references/config.md 获取连接信息（包含 session_id 使用规则）
2. 调用 /references/api/health 确认服务运行中
3. 调用 /references/api/get_window_list 查找目标窗口
4. 调用 /references/api/screenshot 获取带坐标网格的截图
   - [强制] 必须使用 scripts/fetch_screenshot.py 处理响应
5. [强制] 使用五阶段方法论分析截图
   - 禁止跳过任何阶段
   - 每次截图后都必须执行
6. 调用操作 API（click/input_text/press_key 等）
7. 循环步骤 4-6 直到任务完成
```

### 两条铁律

**铁律1：session_id 必须保持一致**
- 整个会话使用同一个 session_id
- 每次调用生成新的会导致图片分散存储
- 详细规则见 `references/config.md`

**铁律2：必须使用现成脚本**
- 截图响应：必须用 `scripts/fetch_screenshot.py`
- batch 响应：必须用 `scripts/batch_results_processor.py`
- 禁止自己编写保存图片的代码

### 核心概念

**坐标系统**：使用百分比坐标（0-100）
- `x=0` 是左边缘，`x=100` 是右边缘
- `y=0` 是上边缘，`y=100` 是下边缘
- 示例：`x=50, y=30` 表示水平居中，垂直30%的位置

**操作方式 (action_method)**：
| 方式 | 体验 | 兼容性 |
|------|------|--------|
| `background` | 无感操作，不抢鼠标键盘 | 兼容性稍差 |
| `hijack` | 会短暂接管，需用户确认 | 兼容性好 |

**详细说明**：见下文"API 公共格式 → 操作方式详解"

## 方法论

### 核心原则：强制五阶段思考

**铁律**：每次截图后，**必须**执行五阶段思考。禁止跳过任何阶段。

```
<thought>
### 阶段1：目标描述（禁止思考位置）
我的目标是：[纯描述任务，如"点击'发送消息'按钮"]
不要说："点击右下角的发送按钮"（错误，包含了位置）

### 阶段2：先验自毁
我的直觉告诉我目标在：[某位置]
我强制判定：这个直觉100%是错的，必定是幻觉
因为实际我看到的是：[描述该区域真实内容]

### 阶段3：全域扫描（强制要求）
**严格规则**：必须仔细观察截图中的每一个元素，禁止遗漏和编造。

**执行要求**：
- **按区域逐行扫描**：从上到下，逐个网格区域观察记录
- **只描述真实存在的内容**：截图里有什么就说什么，没有的绝不能编造
- **记录所有相关元素**：包括文字、图标、按钮、输入框、颜色特征等
- **标记坐标范围**：每个元素记录其所在的网格坐标区域

**扫描模板**：
```
上部区域（坐标 y: 0-30）：
  - (x: 0-20, y: 5-10)：[描述看到的元素，如"窗口标题栏，文字是xxx"]
  - (x: 20-50, y: 8-12)：[描述看到的元素]
  - (x: 50-80, y: 10-15)：[描述看到的元素]
  - [继续扫描直到覆盖整个上部区域]

中部区域（坐标 y: 30-70）：
  - (x: 0-25, y: 35-40)：[描述看到的元素]
  - [继续扫描...完整覆盖中部区域]

下部区域（坐标 y: 70-100）：
  - [继续扫描...完整覆盖下部区域]
```

**禁止行为**：
- ❌ 禁止跳过区域或快速浏览
- ❌ 禁止说"大概在中间"、"应该有"等模糊描述
- ❌ 禁止凭印象或常识推断（如"搜索框通常在右上角"）
- ❌ 禁止遗漏任何可见元素

### 阶段4：排除法筛选
候选网格：[列出所有疑似目标]
- 候选A [网格坐标]：假定是对的，找错误证据 → [发现错误，排除]
- 候选B [网格坐标]：假定是对的，找错误证据 → [发现错误，排除]
- 候选C [网格坐标]：假定是对的，找错误证据 → [找不到错误]

放大确认：放大候选C周围区域
- 精确坐标：[读取坐标标签]
- 如果需要插值：[在网格线之间计算]

### 阶段5：证据确认
该网格的文字/形状是：[准确描述]
上下相邻是：[描述]
置信度：[0-100]%
</thought>
```

### 强制验证：截图确认一切

**铁律**：即使接口返回成功，也必须截图验证结果。

#### 验证格式
```
操作验证：
- 预期：点击后消息应出现在聊天记录中
- 观察：截图显示右侧出现了新的绿色消息气泡
- 结论：操作成功
```

#### 失败重试
```
操作验证：
- 预期：点击后消息应出现在聊天记录中
- 观察：截图显示没有新消息，但输入框有文字
- 分析：可能是没点到发送按钮
- 处理：重新截图，从阶段2开始重新分析。参考常见问题排查分析。
```

### 参数调优决策

当置信度 < 70% 时：

| 问题 | 解决方案 | 参数调整 |
|------|---------|---------|
| 文字模糊 | 增大字体 | `number_size: 12` |
| 网格太密 | 降低密度 | `density: 3.0` |
| 颜色混淆 | 更换颜色 | `color: "#FF0000"` |
| 数字太少 | 增加密度 | `number_density: 1` |

## API 快速索引

| API | 为什么用（目的） | 什么时候不用 | 参考文档 |
|-----|-----------------|-------------|----------|
| `health` | 验证ScreenClaw服务是否可连接，操作前的第一步检查 | 已确认服务正常运行 | api/health.md |
| `get_window_list` | 需要找到目标窗口的window_id（后续操作必需） | 已知window_id，无需查找 | api/get_window_list.md |
| `screenshot` | 需要查看当前界面状态、定位目标元素坐标 | 只执行已知的固定操作序列 | api/screenshot.md |
| `click` | 触发某个功能（如确认、取消）、进入某个页面（如详情页）、激活某个控件 | 需要输入文本、需要长按触发、需要滑动/滚动 | api/click.md |
| `long_press` | 触发长按才能激活的功能（如拖拽起点、显示菜单） | 普通点击即可触发 | api/long_press.md |
| `swipe` | 触摸式滑动（翻页、切换标签、拖拽） | 鼠标滚轮滚动、点击类操作 | api/swipe.md |
| `scroll` | 鼠标滚轮滚动（浏览长内容、列表） | 触摸式滑动、点击类操作 | api/scroll.md |
| `right_click` | 打开上下文菜单、调用特定功能的快捷方式 | 左键操作即可完成 | api/right_click.md |
| `hover` | 触发悬停效果（tooltip、提示框）、显示隐藏的UI交互元素 | 需要点击或其他操作 | api/hover.md |
| `input_text` | 向输入框输入文本内容、填表、搜索 | 只需点击、无需输入 | api/input_text.md |
| `press_key` | 触发快捷键功能（Ctrl+C复制）、发送特殊按键（Enter确认） | 鼠标操作即可完成 | api/press_key.md |
| `wait` | 等待UI动画完成、等待页面加载、等待异步响应 | 不需要等待，可立即执行下一步 | api/wait.md |
| `batch` | 执行多步骤的固定流程（如登录、导航）、减少网络请求次数 | 单步操作、需要根据结果动态决策 | api/batch.md |

## API 公共格式

### 默认调用方式

**推荐使用系统默认工具，无需 Python 环境**：

| 系统 | 推荐工具 | 调用示例 |
|------|----------|----------|
| Windows | PowerShell | `Invoke-RestMethod -Uri $url -Method Post -Headers $headers -Body $body` |
| Linux/macOS | curl | `curl -X POST -H "Authorization: Bearer $token" -H "Content-Type: application/json" -d '{"key":"value"}' $url` |

**为什么推荐**：
- PowerShell 是 Windows 内置，无需安装
- curl 是 Linux/macOS 内置，无需安装
- Python 脚本已提供在 `scripts/` 文件夹，有需要时可使用

### 请求格式

**POST 请求公共请求头**：
```
Authorization: Bearer {token}
Content-Type: application/json
```

**GET 请求（如 health）**：
```
Authorization: Bearer {token}
```

**注意**：token 从 `references/config.md` 获取。

### 完整调用示例

**示例：获取窗口列表（curl）**
```bash
# 基础URL和Token（从config.md获取）
BASE_URL="http://localhost:12261"
TOKEN="your-token-here"

# 调用get_window_list
curl -X GET \
  -H "Authorization: Bearer $TOKEN" \
  "$BASE_URL/api/get_window_list"
```

**示例：点击操作（curl）**
```bash
curl -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"window_id": 12345, "x": 50.0, "y": 30.0, "action_method": "background"}' \
  "$BASE_URL/api/click"
```

**示例：截图（curl）**
```bash
curl -X POST \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"ai_app_type": "claude_code", "session_id": "session-123", "window_id": 12345, "coordinate_type": "grid"}' \
  "$BASE_URL/api/screenshot"
```

**注意**：截图建议使用脚本处理，详见 `api/screenshot.md`。

### 响应格式

**成功响应**：
```json
{
  "success": true,
  "message": "操作成功"
}
```

**带数据的成功响应**（如 screenshot）：
```json
{
  "success": true,
  "message": "操作成功",
  "data": {
    // 具体数据字段
  }
}
```

**失败响应**：
```json
{
  "success": false,
  "error_code": "ERROR_CODE",
  "message": "错误描述"
}
```

### 操作方式详解

**background（无感操作）**：
- 不抢夺鼠标键盘，用户可继续使用电脑
- 通过 PostMessage/SendMessage 注入事件
- 兼容性稍差，某些应用可能不响应
- 无需用户确认

**hijack（劫持操作）**：
- 会短暂激活目标窗口
- 需要用户确认（弹窗）
- 兼容性好，几乎所有应用都支持
- 执行前会请求用户暂停操作

**各 API 支持情况**：
| API | background | hijack | 说明 |
|-----|-----------|--------|------|
| click | ✅ 推荐 | ✅ 备用 | 优先 background，无效时用 hijack |
| input_text | ✅ 推荐 | ✅ 备用 | 优先 background，某些输入框可能需要 hijack |
| scroll | ✅ 有条件 | ❌ | 要求滚动坐标不能被遮挡 |
| press_key | ❌ | ✅ 仅支持 | 只支持 hijack 模式 |
| screenshot | ✅ | ❌ | 只支持 background |

## 常见问题排查

### 操作不成功

按以下顺序排查：

**1. 窗口不对**
**判断标准**：进程具备多个窗口时，通过截图判断操作无效，但screenClaw返回成功。且指令通常为**输入、按键、运动类**。

**选择策略**：
- Windows应用有主窗口和子窗口，它们的window_id不同
- 通过 `get_window_list` 的 `include_children=true` 获取所有窗口

| 操作类型 | 推荐窗口 | 原因 |
|---------|---------|------|
| 点击类（click/long_press/right_click） | 主窗口通常可工作 | 点击事件通常会冒泡到主窗口 |
| 输入类（input_text） | 子窗口 | 输入框通常是子窗口，需要精确定位 |
| 按键类（press_key） | 子窗口 | 按键事件需要发送到具体的接收窗口 |
| 运动类（swipe/scroll） | 子窗口 | 滑动/滚动需要作用到具体的内容窗口 |

**验证方法**：截图查看主窗口和子窗口分别包含哪些内容，根据用户需要操作的目标选择合适窗口

---

**2. 坐标不对**
**判断标准**：
- 如果需要长时间分析思考才能确定坐标，通常就是坐标难以判断，要及时放弃，更换参数重新截图。
- 如果截图验证后的操作结果与预期完全不符（如点击了错误的位置），例如预期点击了“保存”按钮，结果点击了“关闭”按钮。

**网格参数调整**（grid参数）：
- `density`（网格密度）太小：网格线太宽，不好判断元素坐标 → 增大density值（默认5.0，范围0-100）
- `opacity`（网格透明度）太高：网格遮挡内容 → 降低opacity值（默认50，范围0-100）
- `color`（网格颜色）与内容冲突：颜色混在一起，看不清元素 → 更换color值（默认#00FF00绿色）

**数字参数调整**（coordinate参数）：
- `number_density`（数字密度）太小：数字太少，定位困难 → 减小number_density值（默认2，表示每隔2格显示一个坐标）
- `number_size`（字体大小）太小：数字看不清 → 增大number_size值（默认8，范围4-32）
- `number_color`（数字颜色）与背景冲突：数字看不见 → 更换number_color值（默认#00FF00绿色）
- `number_opacity`（数字透明度）太低：数字不够清晰 → 增大number_opacity值（默认100，范围0-100）
- `number_decimal`（小数位）不够：坐标精度不够 → 增加number_decimal值（默认0，范围0-4）

**截图不完整**：请求用户协助，请用户将应用显示在桌面上
- 可能原因：应用跨屏幕了、应用被最小化、应用在托盘里、应用部分超出屏幕可视范围

---

**3. 操作参数不对**
- 优先选择无感操作（`background`），只有当无感操作无效时（截图验证），再选择劫持操作（`hijack`）

---

**4. 用户操作阻塞**
最后的原因，尽可能不要怀疑用户：劫持操作时，用户可能在过程中无意抢夺操作，导致指令执行错乱。需要请求用户暂停操作。

---

### 连接不成功

通过 `health` 检查：
1. screenClaw是否启动
2. 网络是否通畅（检查地址和端口）
3. 认证不通过：鉴权参数是否正确

## 场景模板机制（沉淀与复用）

### 触发时机
任务成功完成后，主动询问：
> "任务已完成。是否要将这次操作流程沉淀为场景模板？下次相同场景可直接执行。"

### 存储位置
场景模板存储在 `references/scenarios/` 下，按应用划分文件夹：
```
references/scenarios/
├── notepad/
│   ├── 新建文件.md
│   └── 打开文件.md
├── wechat/
│   └── 发送消息.md
└── tiktok/
    └── 登录.md
```

### 场景模板格式
```markdown

  ---
  name: {app-name}-{scenario-name}
  description: {什么时候应该用这个场景模板}
  ---

  # {应用名} - {场景名}

  ## 适用场景
  {详细描述这个场景适用的条件，帮助AI判断何时使用}

  ## 目标软件
  - 进程名：xxx.exe
  - 窗口标题关键词：xxx
  - 窗口尺寸比例：宽:高（如 16:9）
    - **获取方法**：从截图的宽高计算，或让用户提供窗口分辨率
    - **重要性**：百分比坐标系下，只有相同尺寸比例的窗口，元素坐标才一致
  - 主窗口子窗口关系：是否需要使用子窗口id，子窗口的类名或标题特征是什么

  ## 全域扫描参考
  按区域描述该应用的典型布局：
  - 上部（A-D行）：{描述，如"标题栏、菜单栏"}
  - 中部（E-H行）：{描述，如"主要内容区、工具栏"}
  - 下部（I-L行）：{描述，如"输入框、按钮、状态栏"}

  ## 常见错误直觉（用于先验自毁）
  | 错误直觉 | 实际情况 |
  |---------|---------|
  | {直觉1，如"输入框在底部"} | {实际情况1，如"输入框在中部偏下，占很大区域"} |
  | {直觉2，如"发送按钮在右下角"} | {实际情况2，如"发送按钮在工具栏右侧"} |

  ## 目标元素识别特征
  ### 颜色状态
  - 选中状态：{描述颜色，如深灰色背景 #2C2C2C}
  - 未选中状态：{描述颜色，如白色背景}
  - 其他状态：{如有其他需要区分的状态}

## 配置管理

### config.json 读取
执行任何API操作前，先读取config.json获取连接信息（地址、端口、token）。
- config.json位置：ScreenClaw根目录下的配置文件

### 用户自定义连接
如果用户提供了ScreenClaw的地址和token：
- 直接使用用户提供的信息进行连接
- 可选：主动询问用户"是否需要将此连接信息保存到config.json？"
- 只有在用户明确确认后，才更新config.json文件

### hijack 操作确认
hijack模式的用户确认弹窗由ScreenClaw自动弹出，技能无需额外处理，只需等待用户确认后继续执行。
