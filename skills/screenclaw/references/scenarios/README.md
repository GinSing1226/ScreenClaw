# 场景模板使用说明

## 目录结构

```
scenarios/
├── README.md                  ← 本文件
├── template.md                ← 场景沉淀的模板格式
├── app_wiki_template.md       ← 应用知识沉淀的模板格式
├── recording_to_scenario.md   ← 从录制产物沉淀场景的分析流程
├── {应用名}/                  ← 按应用英文/拼音名划分
│   ├── app_wiki.md            ← 应用级公共知识（必有，创建应用目录时必须同步创建）
│   └── {场景名}.md            ← 场景模板（按用户常用语言命名）
```

## 检索流程

执行任务前，按以下顺序检索是否已有场景沉淀：

1. **按应用目录名匹配** — 根据目标应用的英文/拼音名，用 Bash 列出文件（Glob 无法访问工作区外的技能目录）：
   - bash：`find "<技能目录>/references/scenarios/{应用名}" -name "*.md"`
   - PowerShell：`Get-ChildItem -Path "<技能目录>/references/scenarios/{应用名}" -Recurse -Filter "*.md" | Select-Object -ExpandProperty FullName`
   - 匹配方式：目录名与应用进程名或常用英文名匹配（如 WeChat.exe → wechat）
2. **按场景文件名匹配** — 如果找到应用目录，读取该目录下所有场景文件（不含 app_wiki.md）的元数据 description，判断是否匹配当前任务
3. **按 app_wiki 扩展匹配** — 如果步骤1找不到应用目录，读取所有 `scenarios/*/app_wiki.md` 的元数据（含进程名、别名），判断是否有匹配的应用
4. **无匹配** — 说明该应用没有沉淀，按全新任务执行

## 模板执行守则

命中场景模板后，进入模板执行模式：

1. **模板优先**：模板是当前任务的主控文档。按模板业务流和节点顺序推进，通用 ScreenClaw 流程只用于模板节点中的截图、定位、marker 反验、操作和验证。
2. **维护执行状态**：在计划或上下文中维护 `active_template_path/current_node/completed_nodes/next_node`。模板较长、上下文变长、收到 `SELF_CHECK_REQUIRED` 或执行高风险节点前，重新打开模板确认当前节点。
3. **节点级验证**：每个需要验证的模板节点，按模板 O（输出）或验证标准截图确认。验证不通过时，先判断窗口、坐标、页面状态或输入变量是否错误。
4. **允许节点降级**：模板可能因产品更新或沉淀不足而失败。同一节点多次执行失败、截图事实与模板明显不符、窗口/坐标复用失效时，将该节点标记为“模板节点降级”，从当前截图重新理解 UI、读取坐标、推理动作并验证结果。
5. **降级不等于放弃模板**：降级后仍保留模板目标、业务流、已完成节点和后续节点。只在失败节点或受影响后续路径使用通用流程，不要回到无模板状态从头探索。
6. **执行后可反哺模板**：如果降级后找到更稳的窗口、坐标、动态定位提示或异常处理，任务成功并经用户确认后再更新模板。

## 沉淀流程

场景模板有两种沉淀入口：

1. **AI 操作后沉淀**：任务成功并截图验证后，主动询问用户是否沉淀。用户确认后，按本流程创建或更新模板。
2. **录制文件沉淀**：用户指定 `record/record_{datetime}` 目录后，读取 `step.json` 和步骤截图，按 `recording_to_scenario.md` 先理解录制内容，再按本流程创建或更新模板。

两种入口的目标一致：把一次操作过程抽象为可复用业务流，而不是把历史坐标和窗口 ID 原样保存。

## 通用抽象原则

1. **先理解业务目的**：明确用户最终想完成什么、哪些输入未来会变化、成功标准是什么。AI 自己操作时通常已知道目标；从录制沉淀时，如果用户没有说明这些关键信息，先集中反问少量问题，不要每一步都问。
2. **合并低价值步骤**：录制或探索中的等待、试错、误输入、连续退格、重复点击等，只在对复现有意义时保留；否则归并或删除。
3. **固定内容固化**：稳定窗口、稳定控件、稳定窗口比例下的固定坐标，可写入固定坐标节点，并尽量组合成 batch 指令。
4. **动态内容提示定位**：依赖用户需求或当前界面状态的目标，例如联系人、文件名、素材、文案、列表项、搜索结果，不固化坐标；写成动态坐标节点，说明截图关注区域、识别特征和定位标准。
5. **高风险动作必须验证**：提交、删除、付款、发布、覆盖文件、发送消息等动作，模板中要要求截图确认或 marker 反验。
6. **窗口锚点要可重建**：模板不要依赖历史 `window_id`。记录进程名、标题关键词、主/子窗口关系和必要截图特征；进程名缺失或不可靠时，用窗口标题通过 `get_window_list` 找候选窗口。
7. **桌面显示器要运行时选择**：桌面级节点不能假设录制时的 `monitor_index` 永远有效。执行前先 `desktop_get_monitors_list`，按当前目标所在显示器截图和操作。
8. **跨进程先执行再验证**：会打开新窗口、新进程、系统弹窗或文件选择框的节点，必须执行跨进程动作后再重新定位并截图确认；不要在旧窗口上验证新窗口结果。
9. **坐标保留小数**：模板中的百分比坐标按录制或截图读数保留小数，例如 `51.5x52.2`、`x=51.5 y=52.2`，不要为了简洁改成整数。
10. **节点标明操作层级**：每个节点要区分主窗口、子窗口、系统弹窗或桌面级操作；不同层级使用不同定位方式和参数，不能混用。类型按 `window_id/main_window_id` 机械判定，业务名称不能覆盖机械类型。
11. **动作记录与状态路径分开**：从录制沉淀时，`step.json.action` 是记录下来的动作事实；hover、无按键鼠标移动等通常不会被录制。截图里已有菜单、hover 态或展开面板时，要结合前后截图判断是否需要补未录制的 `hover`/`mouse_move`/展开动作，但不能把已记录的 `click` 本身改写成 `hover`。
12. **输入内容要语义化**：中文、IME 或输入法场景中，录制文本可能是拼音、英文字符或中间态。模板应沉淀为 `{用户输入}`、`{目标文件名}`、`{搜索关键词}` 等变量，必要时向用户确认最终语义，不把失真的录制文本固化。
13. **完成状态不超出证据**：最终模板的 O（输出）和验证标准只能写录制或截图能证明的状态。若最后截图未显示成功结果，只能写“执行后需截图确认”，不能宣称已完成。
14. **固定坐标绑定窗口信息**：固定坐标必须绑定来源坐标空间的 `window_info.source_width/source_height/scale_factor`。模板执行时用当前截图返回的 `window_info` 调用 `scripts/coord_adapt.*`，按 `direct/verify/relocate` 决策，不手工换算。
15. **按窗口组懒加载复用判断**：不要在执行前统一计算所有窗口。遇到某个窗口组并截图后才计算；同一窗口组缓存一次，窗口尺寸、缩放率、窗口 ID、显示器或页面布局变化后重新计算。
16. **先生成窗口组表**：从录制沉淀模板时，先生成窗口组预处理表，再写业务节点。窗口清单、固定坐标表、操作层级和指令变量必须与窗口组表一致；`Chrome Legacy Window` 等内容子窗口不能写成主窗口。

## 文件创建流程

进入沉淀后：

1. **确定沉淀的应用名**：
   - 直接应用（如微信、记事本）→ 用应用名建目录
   - 模拟器/投屏内的应用（如 MuMu 里的原神、scrcpy 投屏操作手机微信）→ **询问用户要沉淀的是哪个应用**，用被操作的应用名建目录，而非模拟器/投屏工具名
   - 不确定时，直接问用户："沉淀的应用名用什么？"

2. **判断沉淀类型**：

| 情况 | 判断方式 | 操作 | 创建路径 |
|------|----------|------|----------|
| 已有应用，已有同类场景 | 找到应用目录且场景元数据匹配 | 修改已有场景文件 | 直接修改已有文件 |
| 已有应用，未有同类场景 | 找到应用目录但无匹配场景 | 新建场景文件到该目录 | `scenarios/{应用名}/{场景名}.md` |
| 未有应用 | 步骤3也无匹配 | 新建应用目录 + 全套文件 | `scenarios/{应用名}/` 目录 + `app_wiki.md`（按 `app_wiki_template.md` 格式） + `{场景名}.md` |

3. **创建/修改文件** — 场景文件按 `template.md` 格式填写；app_wiki 按 `app_wiki_template.md` 格式填写。已有 app_wiki 的公共知识不在场景文件中重复
4. **更新 app_wiki** — 如果沉淀过程中发现了新的应用级公共知识，同步更新 app_wiki.md
5. **文件路径** — 所有文件创建在 `skills/screenclaw/references/scenarios/` 目录下
